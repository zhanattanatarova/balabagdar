# Project architecture

- Club popularity uses database-backed `views_count`; increment it only through `increment_club_views` so public visitors cannot overwrite counts.
- Club proximity uses optional database-backed `latitude`/`longitude` and browser location is requested only by explicit user action.- `public/sitemap.xml` is generated by `scripts/generate-sitemap.ts` (predev/prebuild) and includes every active club page fetched with the publishable key; don't hand-edit it.
- Club age 3–18 is the retired database default and is treated as "not specified" in display (`hasRealAge`); new clubs must save explicit age and price.
- Announcement phones stay hidden from guests (anon has column-level SELECT without `phone`); only `public_phone`, filled by a DB trigger for admin-created publications with a source URL, is public. Guests read via `announcements_public` or explicit column lists.
- `/` is the city events page (landing); the clubs catalog lives at `/clubs`; `/news` redirects to `/` so old links keep working; club pages stay at `/club/:id`.
- 2GIS rating (`twogis_rating`, `twogis_reviews_count`) is shown only as a separate source-labelled badge, never merged with BalaHub's own `rating`; a DB trigger lets only admins/server jobs change it.
- Publications use optional `club_id` associations, shared `PublicationSource` links and `/publication/:id` detail pages; the guest view exposes source metadata but never phone numbers.
- Event filtering, date formatting and form conversions share `src/lib/events.ts` so visitor timezone cannot change event calendar days; optional end dates are stored as calendar dates.

- Afisha filters (date/age/price/kind) live in `matchesEventFilters` in `src/lib/events.ts` so Aktau-day logic is shared and tested.
- Collections (`collections` table) are resolved client-side by `resolveCollection` in `src/lib/collections.ts` (rule_json or manual ids); empty collections are never shown.
- Deals are announcements with category `promo`/`trial`; a DB trigger forces partner deals to `is_approved=false` and only admins set `is_approved`/`is_promoted`; public reads require `is_approved`.
- Public SELECT policies must not call `has_role` (anon cannot execute it); admin access goes in separate authenticated policies.
- Blog articles render Markdown via react-markdown with `[club:<uuid>]` embeds; the blog link is shown only when a published article exists.
- Shared SiteHeader/SiteFooter wrap every route; all city-based views subscribe through useSelectedCity to the persisted city store, while search preserves filters and updates its city URL parameter on selection.
- City selection uses a portalled modal with focus and scroll management so sticky header containment cannot clip it.
- Catalog photography is imported from local generated assets, while center cards keep their own database photos; decorative imagery must never substitute for a center's actual photo.
